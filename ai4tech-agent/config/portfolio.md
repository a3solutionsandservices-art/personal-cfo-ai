# AI4Tech Lead — Portfolio Context

This file is injected into the Interpreter so recommended actions are grounded
in the lead's actual remit (PRD §7, FR-CTX-1). It is read by the
`StaticContextProvider` and can be replaced by any external context platform
that implements the same interface (FR-CTX-2). Edit freely — it is treated as
configuration, not code.

## Mandate

Drive AI-native software and product delivery across a Payments Technology
organization. Accountable for making the SDLC inner loop, the SDLC outer loop,
and the PDLC AI-native, plus the measurement, governance, enablement, and
platform work that determines whether that transformation succeeds.

## What a "next step" looks like

- **evaluate** — commission a time-boxed technical evaluation against our stack.
- **pilot** — run a bounded pilot with a named team and success metrics.
- **brief-leadership** — prepare a short briefing for technology leadership.
- **update-policy** — revise an engineering policy, guardrail, or standard.
- **feed-roadmap** — add to the platform / delivery roadmap for sequencing.
- **add-to-scorecard** — incorporate into the AI-delivery measurement scorecard.
- **validate** — independently validate a claim before acting on it.
- **watch** — log and monitor; no action yet, revisit if it develops.

## Current portfolio state (what is mid-transformation)

- **SDLC inner loop:** rolling out governed remote developer workspaces;
  evaluating per-developer AI tool spend governance.
- **SDLC outer loop:** standardising AI-assisted code review; piloting AI in
  incident response.
- **PDLC:** introducing spec-driven development; exploring ontology-backed
  requirements.
- **Measurement:** building an AI-delivery scorecard tied to business outcomes.
- **Governance:** establishing guardrails and an evaluation gate for autonomous
  agents.
- **Platform:** investing in context/knowledge engineering and organizational
  memory for AI agents.

## Constraints that shape every recommendation

- Payments / PCI: cardholder data, bank details, credentials, and PII must
  never reach a third-party model. Prefer patterns that respect this boundary.
- Enterprise scale: solutions must work across many teams, not just a demo.
- Bias to evidence over vendor claims; validate before committing budget.
